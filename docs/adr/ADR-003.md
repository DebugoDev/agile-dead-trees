# ADR-003 — Uso dos padrões Adapter, Facade e Translator

- **Status:** Aceito
- **Data:** 2026-10-08
- **Decisores:** Equipe XGH

## Contexto

A integração com os sistemas legados exige adaptação de interfaces, conversão de formatos e isolamento de detalhes técnicos. Essas responsabilidades não devem ser implementadas diretamente no domínio moderno, sob pena de acoplamento e vazamento da linguagem dos legados para a Linguagem Ubíqua.

## Decisão

Utilizar, na modelagem da integração em C#, os padrões **Adapter**, **Facade** e **Translator**:

- **Adapter:** adapta interfaces incompatíveis (por exemplo, `IPrinterClient` para Serial/OPC UA).
- **Facade:** disponibiliza uma interface simplificada para os sistemas legados.
- **Translator:** converte modelos e formatos entre o domínio moderno e os sistemas antigos (JSON → XML/EDI).

## Alternativas rejeitadas

- **Integração direta no domínio moderno:** aumenta o acoplamento e contamina a Linguagem Ubíqua.
- **Um único componente genérico para toda a integração:** concentra responsabilidades diferentes.
- **Compartilhamento dos modelos dos legados:** reduz a independência do domínio moderno.

## Consequências

- Responsabilidades da integração separadas e concentradas na camada de ACL.
- Interfaces mais estáveis para os sistemas modernos.
- Conversão de dados concentrada na camada de integração.
- Necessidade de manter os mapeamentos entre os modelos envolvidos.

## Governança

A ACL fica no contexto Integração de Impressão, conforme o mapa de contextos e a ADR-008. Qualquer novo legado deve entrar por um adapter, nunca por referência direta a partir do domínio.
