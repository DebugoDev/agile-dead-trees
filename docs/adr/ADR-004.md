# ADR-004 — Padrão criacional Factory Method

- **Status:** Aceito
- **Data:** 2026-10-05
- **Decisores:** Equipe XGH

## Contexto

O projeto lida com múltiplas saídas e formatos: diferentes gráficas legadas exigem comunicação via OPC UA ou rede serial. O núcleo de integração (`IntegrationService`) não deve saber como instanciar essas conexões complexas.

## Decisão

Utilizar o padrão **Factory Method** para isolar a lógica de criação dos adaptadores, garantindo que o sistema central dependa apenas da abstração (`Contracts`, `IPrinterClient`). Assim, novas gráficas podem ser adicionadas sem alterar o código existente (OCP).

Aplicação:

1. Definir `PrinterAdapterFactory` como fábrica abstrata/interface estável.
2. `IntegrationService` solicita à fábrica o adaptador correto a partir do ID da gráfica destino.
3. A fábrica instancia `SerialMainframeAdapter` ou `OpcUaMainframeAdapter` e retorna `IPrinterClient`.

## Alternativas rejeitadas

- **Instanciação direta no serviço:** acopla o domínio a classes concretas e quebra o DIP.
- **Condicionais `if/else` para escolher o adaptador:** exige alteração do serviço a cada nova gráfica.

## Consequências

- Desacoplamento entre o serviço de integração e a instanciação concreta dos adaptadores de hardware/comunicação.
- Maior extensibilidade para adicionar gráficas.
- A fábrica passa a ser um ponto de mudança que precisa de testes.
